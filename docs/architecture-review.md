# 订阅库架构与逻辑审查

审查日期：2026-10-19。基线为 `flutter_inapp_purchase 11.0.3` 与
OpenIAP Apple / Google `4.0.3`，范围为当前 `lib/` 全部模块、示例和相关测试。
本文区分已有正确设计、本轮修正与宿主职责；不提供旧接口兼容层。

## 结论与职责划分

当前分层适合本库的职责，无需为了减少文件数合并两端实现，也无需继续拆出策略框架。
本轮需要改动的重点是交易时序、连接管理、错误分类和状态语义。价格计算、工作计数、
缓存序列化与平台适配契约保留原有边界。

| 模块 | 审查结果与处理 |
| --- | --- |
| 配置与公共入口 | 协调器持有配置套餐快照；统一等待 `init()`。移除 `ready`、`isReady` 和公开缓存加载入口，避免多份就绪状态。默认入口仅导出集成 API、状态模型和适配契约。 |
| 套餐与目录 | 保留宿主套餐映射、商品去重和精确优惠解析。协调器展示与购买使用同一配置范围，未注册套餐不能因 SKU 相同而显示可购买。购买统一使用 `purchasePlan`。 |
| 价格与试用 | 正常续费价、首期优惠与试用分开；平均价使用商店数值、币种精度和显式除数。Apple 按订阅组查询资格，Google 按所选优惠判断免费阶段。未发现需要额外重构的问题。 |
| 交易编排 | 恢复与事件共用串行队列。事件在到达时关联当前购买，避免处理时误关联后来发起的购买。 |
| 单笔交易处理 | 处理器只负责状态检查、真实性验证、当前权益确认、商店完成与独立记录，不直接修改全局权益。保留此分离。 |
| Apple 适配 | 使用 StoreKit 已验证当前权益与订阅组状态；签名通过不等于当前订阅有效。不根据未来续订商品猜当前权益归属。 |
| Google 适配 | 验证原始签名并核对购买令牌、商品和包名；当前订阅与签名购买记录关联。修正暂停与签名失败的统一状态语义。 |
| 全局权益 | 按全部配置商品聚合，有效商品优先；单笔失败不能直接覆盖其他有效商品。交易处理后重新查询，不复用交易前开始的权益查询。 |
| 权益缓存 | 缓存只负责序列化与六小时新鲜度检查；配置范围和查询失败回退由协调器判断。回退保留原始快照时间；部分组查询失败只使用失败组商品的缓存。 |
| 连接与生命周期 | 连接真实性以底层插件共享状态为准，合并进行中的初始化与关闭，关闭结束后才允许后续连接。前台刷新保留互斥。 |
| 工作状态与回调 | 工作计数与 `finally` 保证异常、并行查询后的状态收尾；只导出只读快照。观察器、日志和交易记录失败不改变商店结果。 |
| 释放 | 取消购买与生命周期监听，结束等待中的购买，关闭已建立连接；异步结果在释放后不再更新通知器。未初始化的实例也能安全释放。 |

## 本轮修正的问题

### 恢复期间漏掉事件

原先恢复过程中直接忽略购买事件。Google 官方说明，事件也可能来自应用外购买或
待批准交易转为已购买；不能假定恢复期间收到的都是重复事件。

现在恢复批次与事件串行执行，仅跳过本批次已经成功处理的同一笔重复交易。
去重键为商店标识、商品标识和非空交易 ID；新交易与本批次处理失败交易仍继续处理。
集合只在本批次事件中使用，不引入永久缓存，也不阻止未来恢复重试。

### 旧事件误结束新购买

原先事件排队后才查找当前购买。同一 SKU 的旧交易可能在新购买开始后才处理，
从而错误完成新购买的 Future。现在在事件到达时捕获当前操作，处理时同时核对
操作对象与商品；不匹配的交易作为静默同步处理。

### 查询错误被合并或误分类

原先商品加载吞掉错误，购买入口只能返回笼统的商店不可用；单笔权益查询也可能把
查询失败解释为验证失败。现在内部商品查询保留异常，公开 `loadProducts()` 仍返回
加载是否成功；购买及交易处理保留可取得的官方 `ErrorCode`。

没有有效当前权益使用 `subscriptionInactive`；StoreKit 分组状态查询异常使用
`storeQueryFailed`。连接失败、签名失败和订阅失效各自分类，业务层无需比较错误字符串。

### 自建连接状态落后于插件，关闭与重连交叉

插件自己维护连接状态，并在原生 `connection-updated` 后标记断连。原先本库根据
自身布尔状态跳过插件检查，导致下一次查询可能先失败。插件关闭连接也要等待原生返回，
未等待关闭完成就开始新查询会继续使用正在关闭的连接。

现在调用插件的 `initConnection()` 检查共享状态；插件已连接时自行直接返回。
库只合并进行中的连接与关闭，并让后续连接等待关闭完成。超时不等于断连，
仅按官方连接类错误失效连接；不增加固定轮询或自动重试购买。

### Google 状态语义不准确

`isSuspendedAndroid` 只能证明商店返回暂停，不能确定是账号保留还是用户暂停，
也不能当作 Apple 的扣款重试。统一状态新增 `suspended`，对应交易失败为
`subscriptionSuspended`；`billingRetry` 保留给 StoreKit 明确返回的扣款重试状态。

本地签名验证失败也不能证明商店撤销。现在返回 `unavailable` 与
`localVerificationFailed`，不采用查询失败缓存。

Google 当前订阅和签名购买记录来自两次查询。若前者返回有效，后者已明确暂停或仍待付款，
不能继续授予权益。关联时同时要求签名购买为已购买且未暂停；其他有效购买仍可授予权益。

### 重复初始化接口与展示范围

移除单独的就绪 Future、就绪布尔值、公开缓存加载方法和冗余生命周期标志。
调用方等待 `init()` 即可，购买和恢复也会等待同一次初始化。
未注册套餐统一返回 `planNotConfigured`，使展示与购买规则一致。

## 合理保留的代码

- **两端适配器和内部 Helper**：购买参数、真实性验证、完成交易和权益来源存在实际差异。
  适配器负责调用商店，Helper 负责签名或状态解析；不把这些分支重新塞回协调器。
- **工作计数器**：商品、资格与权益查询可能并行，单个 `isLoading` 布尔值会提前结束加载。
  计数与 `finally` 是必要的状态管理；组件、遮罩和文案始终由宿主实现。
- **iOS 恢复后的购买查询**：插件 `restorePurchases()` 内部查询购买，但返回 `void`；
  适配器还需要购买列表才能逐笔处理。当前公共 API 下不能直接删除后续查询。
- **Google 当前订阅查询与购买查询**：前者提供当前订阅结果，后者提供原始签名、
  令牌与暂停信息。当前不把两种返回值视为等价，不为减少调用而删掉验证证据。
- **权益缓存与回退边界**：存储层不承担平台判断；单笔处理器不承担整体授权；
  明确失效与查询异常不能混用。六小时是库的离线快照约定，商店状态仍以查询结果为准。

## 接入方保留什么

宿主配置自己的套餐枚举、商品映射和可选优惠，直接持有协调器并监听
`plans`、`activity`、`accessState`。页面只按所选套餐调用 `purchasePlan`。
普通 Google base plan 不填写 `offerId`；需要指定优惠时在套餐配置中填写一次。

价格解析、平均价计算、试用查询、初始化合并、购买互斥、交易队列和加载状态由库负责。
套餐展示策略、额外优惠资格、loading 样式、本地化文案、账户标识、页面路由、埋点、
提醒和产品 API 保留在宿主。`transactionReporter` 仅异步记录已完成交易，
不承担服务端授权、持久化或自动重试保证。
